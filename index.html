    What is Computer Vision?

    Computer Vision (CV) is a field of AI that enables machines to derive meaningful information from images. Some of the things that means in practice:

    These problems feel easy to us because humans are trained on many years of image data. Computers start from something very different — so before asking how they cope, look at what they actually receive.

    02

    What a computer actually sees

    A digital image is a matrix of size (H, W, C) made of numbers called pixel values, typically ranging from 0 to 255. H, W and C are the height, width and number of channels. A grayscale image has 1 channel; a colour image has 3. (PyTorch tensors are stored channels-first, as (C, H, W).)

    03

    Why computer vision is hard

    Is CV easy? To find out, Google's Vision API was asked what it detects in the image below. The result was bad.

    Three classic difficulties

    The scope of CV is enormous

    • CV powers industry-leading products such as self-driving cars, automated robots, drones and medical image analysis.
    • It also works alongside other branches of AI such as speech and NLP. In speech recognition, audio chunks are converted into 2D matrices (mel spectrograms) and treated like images.
    • In NLP, CV techniques appear in image captioning and, very recently, image synthesis from prompts.
    04

    Why deep neural networks for images?

    To see why a deep neural network (DNN) is a sensible choice, look at how the visual cortex works. It is arranged in layers: as information passes from the eyes to deeper parts of the brain, higher and higher order representations are formed. A DNN works in a similar way, so using one to analyse images makes perfect sense.

    But what about the architecture? Is a vanilla NN (an MLP) a suitable fit for images? The next parts answer exactly that.

    05

    The scenario: a hammer and a screw

    In earlier lectures we learned about ANNs and where to use them. Now we try fitting a vanilla neural network (the hammer) to a very different kind of data, images (the screw), and see why that does not make sense.

    The job

    You are a Data Scientist at Amazon. The goal is an automated system that assigns a clothing product to its master category: 10 classes.

    The first attempt

    It is a multi-class classification problem on a labelled dataset, and you have just studied ANNs, so you apply one. It gives very poor results.

    The question

    Why didn't the ANN work, and what else would? The inventory: a vanilla NN (hammer) and a CNN (the new tool).

    The data

    The dataset is a collection of real-world clothing images (the open-source clothing-dataset-small). It already comes divided into train, validation and test folders, each with one sub-folder per class, so no split has to be created.

    • Every image has a different size. That is normal for real-world data but not ideal: a batch needs all samples to be the same size. Preprocessing handles this next.
    • The classes are imbalanced. For this lecture we work with the distribution as given; common techniques for imbalanced data come later.
    06

    Preprocessing

    Three kinds of preprocessing are needed before the data reaches a network. First the data folders are mounted in PyTorch with torchvision.datasets.ImageFolder, which assumes a root/class_name/xxx.png layout, lazily loads the images and infers each label from its folder name. A DataLoader then adds batching, shuffling and parallel loading.

    Shape

    Resize

    A batch needs identical sizes, so every image is resized to a fixed 128 × 128.

    Value

    Rescale

    transforms.ToTensor() converts uint8 to float32, rescales 0–255 to 0–1, and reorders (H, W, C) to (C, H, W). Without scaling, images with large pixel values would dominate the loss and the weight updates (think black cat vs white cat).

    Shape · MLP only

    Flatten

    Neural networks need each sample to be 1D. A batch of bs × 3 × 128 × 128 becomes bs × 49,152.

    Flatten is kept as a layer inside the model rather than in the preprocessing stack. It is a non-standard preprocessing step, and it is not needed when working with CNNs.

    Code: mounting data and the preprocessing pipeline 
    train_data = datasets.ImageFolder("clothing-dataset-small/train")
val_data   = datasets.ImageFolder("clothing-dataset-small/validation")
test_data  = datasets.ImageFolder("clothing-dataset-small/test")

height, width = 128, 128
data_preprocess = transforms.Compose([
    transforms.Resize((height, width)),  # shape preprocessing
    transforms.ToTensor(),               # value preprocessing: rescales to [0, 1]
])
train_data.transform = data_preprocess
val_data.transform   = data_preprocess
test_data.transform  = data_preprocess

train_ds = DataLoader(train_data, batch_size=32, shuffle=True)
val_ds   = DataLoader(val_data,   batch_size=32, shuffle=False)
test_ds  = DataLoader(test_data,  batch_size=32, shuffle=False)
    07

    Training a vanilla neural network

    We start with the vanilla NN, check its performance on the test set, then switch to a CNN and see how much better it does.

    Model architecture

    A neural network is made of an input layer, a few hidden layers and an output layer. Each neuron trains on a distinct set of features based on the previous layer's output, and the connections between neurons (the weight matrix W) are what let the network recognise patterns. Here: flatten, two hidden dense layers (1,024 and 256 units) with ReLU, and a 10-unit output layer.

    Code: ANNModel 
    class ANNModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.flatten = nn.Flatten()
        self.fc1 = nn.Linear(height * width * 3, 1024)  # hidden layer 1
        self.fc2 = nn.Linear(1024, 256)                 # hidden layer 2
        self.fc3 = nn.Linear(256, 10)                   # output layer
        self.relu = nn.ReLU()

    def forward(self, x):
        x = self.flatten(x)
        x = self.relu(self.fc1(x))
        x = self.relu(self.fc2(x))
        return self.fc3(x)  # raw logits: CrossEntropyLoss applies log-softmax internally

    Loss function and optimizer

    Cross-entropy for multi-class classification

    Suppose a 4-class task: is the object a dog, cat, horse or cheetah? The network outputs one raw score (logit) per class. Softmax converts logits into probabilities, and cross-entropy measures the distance between those probabilities and the true label.

    In PyTorch, nn.CrossEntropyLoss expects integer class labels (not one-hot) and combines LogSoftmax + NLLLoss internally. The model's last layer must therefore output raw logits, not softmax probabilities.

    Adam as the optimizer

    • It combines the momentum idea with Root Mean Square Propagation (RMSProp), using adaptive per-parameter learning rates to converge quickly.
    • It is computationally efficient and needs little memory.
    • Like every gradient-based optimizer on a non-convex loss, it finds a good (local) minimum, not a guaranteed global minimum.
    Code: loss function and optimizer 
    criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters())

    Training and evaluation

    Training for 10 epochs, the vanilla NN reaches about 56.5% training accuracy and 48.7% validation accuracy. Explore the curves below. On the test set it scores 42.74%.

    08

    Swapping in a CNN

    Hammering image data did not give good results, so let's reach for the right tool. We replace the first 1,024-unit dense layer with a simple convolution block and keep a dense hidden layer and output layer after it. A typical convolution block is an nn.Conv2d layer, an activation (ReLU) and an nn.MaxPool2d layer. (Each piece is explained in detail in the sections that follow.)

    Code: CNNModel 
    class CNNModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(in_channels=3, out_channels=16, kernel_size=3, stride=1, padding=1)
        self.relu = nn.ReLU()
        self.pool = nn.MaxPool2d(kernel_size=2)
        self.flatten = nn.Flatten()
        flattened_size = 16 * (height // 2) * (width // 2)
        self.fc1 = nn.Linear(flattened_size, 256)
        self.fc2 = nn.Linear(256, 10)

    def forward(self, x):
        x = self.relu(self.conv1(x))   # (bs, 16, 128, 128)
        x = self.pool(x)               # (bs, 16, 64, 64)
        x = self.flatten(x)
        x = self.relu(self.fc1(x))
        return self.fc2(x)             # raw logits

    The same cross-entropy loss and Adam optimizer are used, and the model is trained for the same 10 epochs.

    Head to head: hammer vs screwdriver

    With the same data, loss, optimizer and epochs, swapping a single dense layer for one convolution + pooling block gives a clear jump in accuracy. Where we have a screw (image data), a specialist tool (CNN) beats the hammer (vanilla NN).

    Reference-run note: the lecture text quotes roughly 27% for the vanilla NN, while the evaluation output shown here reports 42.74%. Exact numbers vary from run to run; the CNN's ~51% appears in both.

    10

    Why the hammer failed: three problems with MLPs

    11

    What the screwdriver needs

    From the discussion so far, we need a system that:

    • is robust to translation (position): convolution gives translation equivariance, and pooling adds local invariance;
    • leverages the spatial correlation between pixels;
    • focuses only on local connectivity.

    Taking inspiration from the visual cortex, image data has three essential properties:

    1

    Locality

    Neighbouring pixels in an image are correlated.

    2

    Stationarity

    Similar patterns appear multiple times in an image.

    3

    Compositionality

    Higher-level features are extracted by combining (pooling) lower-level features.

    Can we add these properties to a vanilla NN?

    • Sparse connections for locality. Local features are highly correlated, far-away ones much less, so drop the far-away connections. This restricts each neuron's receptive field (here from 5 inputs to 3). The receptive field with respect to the initial layers grows as we go deeper.
    • Parameter sharing for stationarity. Since patterns repeat across an image, share the same weights at every position.

    Together these two operations greatly reduce the number of parameters while preserving the inductive bias of the input signal. Unlike in an MLP, the parameter count no longer depends on the input image size: only on kernel size, input channels and number of filters.

    In 2D, these two ideas give a set of learnable parameters of size k × k called a filter or kernel. The computation those kernels perform is called convolution.

    12

    Convolution, step by step

    In deep learning, an (image) convolution is an element-wise multiplication of two matrices followed by a sum:

    1. Take two matrices of the same dimensions.
    2. Multiply them element by element (not a dot product, just plain multiplication).
    3. Sum the results.

    Technical note: what deep-learning libraries call convolution is strictly cross-correlation: the kernel is not flipped. Since kernels are learned, the difference does not matter in practice.

    The kernel slides over the image

    A kernel is a small matrix that slides across a larger image, left to right and top to bottom. At each position, the neighbourhood of the image under the kernel is convolved with it and the result stored. By looking at neighbouring pixels again and again, a kernel can correlate features in the image: for a car on a road, sliding kernels can pick out the car's edges (its shape) by comparing pixels on the car with pixels on the road.

    Try it. In the explorer, 10 is a bright pixel and 0 a dark one. The default kernel's top row rewards bright pixels and its bottom row rewards dark ones, so it detects a horizontal boundary. Switch the image or kernel and see what the kernel responds to.

    • The first window covers only bright pixels, so the products cancel and the sum is 0: the first output value.
    • The kernel then shifts one column right and repeats. The size of each shift is the stride; a stride of (2, 1) would shift two columns horizontally and one row vertically.
    • After a few positions, the output has picked out the horizontal line separating the bright and dark regions.
    • Because the same kernel slides everywhere, convolution is translation equivariant: wherever the line is, the kernel responds with the same pattern of values, shifted to the matching place in the output. (Making the final prediction invariant to small shifts is mainly pooling's job.)

    Detecting vertical edges on a real image

    With the right kernel a computer can detect vertical edges. Applying OpenCV's Sobel filter (dx=1, dy=0 measures intensity change along x, so it responds to vertical edges) to the grayscale version of the image gives:

    Code: Sobel vertical-edge filter 
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)   # cv2.imread returns BGR order
# ddepth: 64-bit float output (Sobel output can be negative)
# dx=1, dy=0: change along x, so it responds to VERTICAL edges
output = cv2.Sobel(gray, ddepth=cv2.CV_64F, dx=1, dy=0, ksize=3)
output = cv2.convertScaleAbs(output)           # take |output| and convert to 8-bit

    Try the explorer with the "Bright left, dark right" image and the vertical-edge kernel; the Sobel kernel's negative response (dashed borders) is why the code takes the absolute value.

    Stacking filters and handling colour

    • Several filters at once. Apply a horizontal and a vertical edge detector separately and stack their outputs. The output gains a third dimension equal to the number of filters.
    • Colour input. If the input has more than one channel, each kernel has a matching depth (the number of input channels) and the convolution runs over the whole volume. With 2 filters on the lecture's example the output is 4 × 4 × 2.
    • Learned, not handcrafted. Many more kernels than horizontal and vertical are possible, and which ones matter depends on the problem and dataset. In deep learning we only specify the kernel size and number of kernels, and gradient descent (backpropagation) learns the values. These learnable kernels form a Conv layer.

    How many parameters does a conv layer have?

    It depends on the filter size, the number of filters and the number of input channels. It does not depend on the height and width of the input image. For one filter of height m, width n over d input channels there are (m·n·d) + 1 parameters (the +1 is the bias), so for k filters:

    parameters = ((m × n × d) + 1) × k

    For our CNN (16 filters of 3 × 3 on a 3-channel input): ((3·3·3) + 1) · 16 = 28 · 16 = 448, matching the model summary above. Change the image size below and compare how a dense layer and a conv layer react.

    Code: verifying the count, and the equivariance demo 
    conv = nn.Conv2d(in_channels=3, out_channels=16, kernel_size=3, stride=1, padding=1)
n_params = sum(p.numel() for p in conv.parameters())
print(tuple(conv.weight.shape), tuple(conv.bias.shape), n_params)
# (16, 3, 3, 3) (16,) 448

# Convolution is translation EQUIVARIANT: shift the input, the output shifts the same way
x = torch.randn(1, 1, 12, 12)
k = nn.Conv2d(1, 1, kernel_size=3, padding=0, bias=False)
shift = 2
y = k(x)
y_of_shifted = k(torch.roll(x, shifts=shift, dims=3))
print(torch.allclose(y[..., :-shift-2], y_of_shifted[..., shift:-2], atol=1e-6))
# True

    Why kernels are odd-sized

    We have always used 3 × 3 rather than 2 × 2 or 4 × 4. With an odd size, the pixels of the previous layer sit symmetrically around the output pixel, and the kernel's centre is a valid integer (x, y) coordinate. Even kernels are not impossible, but they need asymmetric padding to keep the output size.

    13

    Padding, stride and output size

    In the explorer above, a 6 × 6 input gave a 4 × 4 output. The kernel only moves where it fully fits, so the output dimension is o = n − f + 1 (n input size, f kernel size): 6 − 3 + 1 = 4. The output shrinks with every convolution, and corner pixels are under-used. The fix is padding: adding pixels (zeros) around the border before convolving.

    Padding

    Without padding the 3 × 3 kernel would "hang off" the edge when centred on the pixel at (0, 0), so we either start where the kernel fully fits ("valid" convolution, output shrinks) or pad the border with zeros ("same" convolution). Padding is useful because:

    1. it preserves information at the image corners, which would otherwise be under-used;
    2. the height and width no longer have to shrink after every convolution.

    With padding width p on every side, the output size becomes o = n + 2p − f + 1. The tool below counts how many kernel positions cover each pixel of a 6 × 6 image.

    Stride

    Stride sets how far the kernel slides each step. A larger stride shrinks the output faster. Its effects: less memory for the output, smaller spatial dimensions that cut computation in later layers, and skipping largely redundant overlapping positions (though too large a stride can skip useful detail). Set stride 2 in the explorer in section 12 to watch it.

    o = ⌊(n + 2p − f) / s⌋ + 1n input size · p padding · f kernel size · s stride
    Code: checking the formula against PyTorch 
    n, f = 12, 3
for p, s in [(0, 1), (1, 1), (0, 2), (1, 2)]:
    out = nn.Conv2d(1, 1, kernel_size=f, stride=s, padding=p)(torch.zeros(1, 1, n, n))
    print(p, s, out.shape[-1], math.floor((n + 2*p - f) / s) + 1)
# p=0,s=1 -> 10   p=1,s=1 -> 12   p=0,s=2 -> 5   p=1,s=2 -> 6

    The Conv2d arguments, one by one

    ArgumentMeaning
    in_channelsNumber of channels of the input (3 for RGB). PyTorch always requires it explicitly; there is no shape inference from an input_shape argument.
    out_channelsNumber of unique filters this layer learns; also the number of output channels.
    kernel_sizeSize of the kernel: an integer or a 2-tuple such as (3, 3) or (5, 5).
    strideDistance the kernel slides, as an integer or a 2-tuple. Default 1.
    paddingAn integer (pixels of zero padding per side) or, since PyTorch 1.9, the strings "same" / "valid" (only with stride 1). padding=1 with a 3 × 3 kernel and stride 1 keeps the spatial size.
    activationThere is no such argument in PyTorch: convolution and activation are separate layers, e.g. nn.Conv2d(...) followed by nn.ReLU().
    14

    Pooling and flattening

    Our CNN also used MaxPool2d, which has no learnable parameters. Pooling reduces the height and width of the feature maps. That reduces computation and the number of parameters in the layers that follow, and makes the representation more robust (locally invariant) to small shifts in the input. Stacking layers supports compositionality: deeper layers see larger regions of the image.

    • Max pooling: slide an (f, f) window with a stride and keep the maximum in each region. Used between conv layers.
    • Average pooling: keep the average instead. In modern architectures, (global) average pooling is common just before the fully connected layers.
    o = ⌊(n − f) / s + 1⌋n input size · f pooling window · s stride
    Code: pooling layers in PyTorch 
    nn.MaxPool2d(kernel_size=2)  # stride defaults to kernel_size
nn.AvgPool2d(kernel_size=2)
# kernel_size: window size (int or 2-tuple), a non-learnable "filter" taking max or mean
# stride: like Conv2d; default None means stride = kernel_size

    Flattening

    After convolution, activation and pooling we have pooled feature maps. Flattening literally turns them into one long column vector, because the data is about to enter an artificial neural network. Multiple pooled feature maps become a single long input vector that the dense layers process further.

    Key takeaways

    1 · MLPs are a poor fit

    Flattening destroys spatial structure and needs a huge number of weights.

    2 · Convolution is the fix

    Local connectivity + parameter sharing give far fewer parameters and translation equivariance.

    3 · Know your formulas

    Pooling has no learnable parameters; sizes and counts follow the formulas below.

    Output size

    ⌊(n + 2p − f)/s⌋ + 1

    Conv parameters

    ((m·n·d) + 1) · k

    Pooling parameters
